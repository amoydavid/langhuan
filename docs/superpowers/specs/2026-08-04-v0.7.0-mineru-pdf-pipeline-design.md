# 琅嬛 v0.7.0 MinerU Cloud PDF 解析与资产归档设计规格

> **背景**：本版本原编号 v0.3.0/v0.8.0，经多次 ROADMAP 调整后定档为 **v0.7.0**，排在 v0.6.0（Workspace API Key、MCP 与程序化访问）之后、v0.8.0（可靠性与运维）之前。撰写本规格时，v0.3.0~v0.6.0 的能力均已落地：多格式解析、ChunkSet/ChunkRevision 事实模型、Embedding 与混合检索、Web Console、Workspace API Key 与 MCP 工具。因此本版本**不**重新发明 chunker/embedding/检索，而是把 PDF 解析产出的 Markdown 接入已有流水线。

## 1. 背景与定位

v0.6.0 已交付完整的知识处理与检索闭环，但 `ingest.allowed_file_types`（`config.example.yaml:25-33`）只接受 `markdown/md/txt/csv/xlsx/docx`，PDF 会在导入阶段返回 HTTP 415（ROADMAP v0.3.0 约定）。PDF 是企业知识库最重的输入格式，v0.7.0 补齐它。

v0.7.0 在现有 `DocumentRevision → DocumentChunkSet → Chunk → ChunkRevision` 事实模型和单 active Generation 流水线之上，新增一个 PDF parser 适配器（MinerU Cloud），并把解析产物（normalized Markdown + 图片资产）归属到 DocumentRevision，使 PDF 与其它格式走完全相同的 chunk/embed/index 链路。MinerU 只是一个 parser adapter，不是领域模型的一部分；后续接入其它 PDF parser 只要实现同一份 parser 合同即可复用资产归档与 normalized Markdown 写入。

参考：MinerU API 文档 `https://mineru.net/apiManage/docs`。设计基于其精准解析 API：token 鉴权、`/api/v4/file-urls/batch` 申请批量上传地址、异步提交/轮询、`/api/v4/extract/task` 查询任务、`pipeline` / `vlm` 模型版本。

## 2. 目标

v0.7.0 交付：

- **对象存储可选切换**：新增 S3-compatible 存储适配器，与现有本地文件系统适配器通过配置二选一；原始 PDF、raw Markdown、图片资产统一走对象存储或本地磁盘。
- **MinerU parser 适配器**：实现 `parser/minerucloud`，支持申请上传地址 → PUT PDF → 轮询 → 下载 Markdown/zip → 提取 Markdown。
- **异步解析**：在 worker 层把 MinerU 的「提交 + 长轮询」异步语义适配到现有 `document_parse_start` / `document_parse_poll` 任务，**保持同步 `DocumentParser` 接口不变**，现有 5 个本地 parser 零改动。
- **AssetResolver**：扫描 Markdown 图片引用（`![](url)`、`<img>`、data URI、zip 相对路径、远程 URL），下载/解码后写入对象存储，生成 `document_assets` 并把引用替换为 public URL。
- **Parser Provider 凭据**：复用 `model_providers` 表存储 MinerU token（AES-GCM 加密），在应用层引入 ParserProvider 能力域，与现有 Embedding Provider 能力域解耦。
- **PDF 接入统一流水线**：PDF 产出的 normalized Markdown 自动进入现有 chunk/embed/index，到达 active Generation，可被 REST/Web/MCP 检索。
- **Web Console 前端**：PDF 上传入口、解析阶段进度、warning 展示、失败诊断、资产预览。

## 3. 非目标

- 不重做导入 REST API 合同（沿用 v0.4.0 的 workspace-scoped document ingest）。
- 不改变 `DocumentRevision / DocumentChunkSet / Chunk / ChunkRevision` 事实模型结构，只在 revision 上新增资产与 raw markdown 归档。
- 不改变同步 `DocumentParser` 接口（`Parse / Supports`）的现有签名；MinerU 的异步语义由 worker 层和 MinerU 专用接口承载。
- 不在 `models` 表为 MinerU 建「子模型实例」行（parser 没有 embedding 那样的模型实例概念，模型版本 `vlm`/`pipeline` 作为 provider 配置或 parser 参数）。
- 不实现文档删除对对象存储的 GC（删除只退役 DB 投影，对象存储清理留到 v0.8.0 可靠性版本）。
- 不做 LLM 回答、Rerank、crawler。
- 不保存 MinerU 完整 zip/json 作为必交付产物（可选项，见 §15）。

## 5. 对象存储与存储端口

### 5.1 可切换的存储后端

新增 S3-compatible 适配器，与现有 `local/` 通过配置二选一。`StorageConfig` 扩展 driver 字段：

```go
type StorageConfig struct {
    Driver         string         `yaml:"driver"`           // "local" | "s3"
    RawDocumentDir string         `yaml:"raw_document_dir"` // driver=local 时使用
    S3             S3Config       `yaml:"s3"`               // driver=s3 时使用
    Assets         AssetsStorageConfig `yaml:"assets"`       // 资产限制
}

type S3Config struct {
    Endpoint       string `yaml:"endpoint"`
    Region         string `yaml:"region"`
    Bucket         string `yaml:"bucket"`
    AccessKey      string `yaml:"access_key"`
    SecretKey      string `yaml:"secret_key"`
    ForcePathStyle bool   `yaml:"force_path_style"`
    PublicBaseURL  string `yaml:"public_base_url"`
}

type AssetsStorageConfig struct {
    MaxCountPerDocument int      `yaml:"max_count_per_document"`
    MaxImageSizeBytes   int64    `yaml:"max_image_size_bytes"`
    AllowedMimeTypes    []string `yaml:"allowed_mime_types"`
}
```

`cmd/langhuan` 装配时按 `cfg.Storage.Driver` 选择实现：`local` → 现有 `local.NewRawDocumentStore` + 新增 `local.NewAssetStore`；`s3` → 新增 `s3.NewStore`（同时实现 `RawDocumentStore` 和 `AssetStore`）。

### 5.2 S3 key 规则

同一 bucket，按 key prefix 区分用途（`workspace_id/knowledge_base_id/document_id/revision_id` 均为 UUIDv7）：

```text
raw-documents/{workspace_id}/{knowledge_base_id}/{document_id}/{revision_id}/original.{ext}
parser-results/{workspace_id}/{document_id}/{revision_id}/{job_id}/raw.md
assets/{workspace_id}/{document_id}/{revision_id}/{asset_id}.{ext}
```

约束：

- key 不直接拼接未清理的用户文件名；扩展名只从 MIME allowlist 或清理后的文件名派生。
- 支持 path-style endpoint，兼容 RustFS / MinIO / 阿里云 / 腾讯云。
- `public_url = strings.TrimRight(public_base_url, "/") + "/" + 按 path segment escape(key)`，不依赖 bucket 公开列目录。

### 5.3 存储端口调整

`AssetStore` 现状是 `ObjectInput.Data []byte`（全量内存）。PDF 单张图片通常 < 10MB，可接受全量载入；**保持 `[]byte` 不变**，避免为 PDF 过度改造。两个适配器（local / s3）各自实现 `RawDocumentStore` 和 `AssetStore`。

新增 `local/asset_store.go`（参考 `local/raw_document_store.go` 的 symlink 防护与原子重命名模式）和 `s3/store.go`（AWS SDK for Go v2）。

## 6. MinerU 适配器与异步解析

### 6.1 两层 parser 接口

保持同步 `DocumentParser` 接口不变（现有 5 个 parser 零改动）。为 MinerU 这种「提交 + 长轮询」型 parser 在 `ports/parser` 新增异步专用接口：

```go
// AsyncDocumentParser 是可选的异步 parser 能力。
// worker 层 parse_start/parse_poll 通过类型断言检测 parser 是否实现该接口；
// 不实现则继续走同步 Parse 一次性完成。
type AsyncDocumentParser interface {
    Start(ctx context.Context, input AsyncParseInput) (*AsyncParseStart, error)
    Poll(ctx context.Context, input AsyncParsePollInput) (*AsyncParsePollResult, error)
}

type AsyncParseInput struct {
    ParseInput                      // 复用 FileType/Title/Content/Metadata
    WorkspaceID     uuid.UUID
    KnowledgeBaseID uuid.UUID
    DocumentID      uuid.UUID
    RevisionID      uuid.UUID
    JobID           uuid.UUID
}

type AsyncParseStart struct {
    ExternalJobID string          // MinerU batch_id/task_id
    Payload       map[string]any  // 持久化到 jobs.payload（不含 token）
    Status        AsyncStatus     // submitted
}

type AsyncParsePollInput struct {
    AsyncParseInput
    ExternalJobID string
    Payload       map[string]any
}

type AsyncParsePollResult struct {
    Status   AsyncStatus           // running | succeeded | failed
    Document *ParsedDocument       // succeeded 时填充
    Payload  map[string]any        // 更新到 jobs.payload
    RetryAfter time.Duration       // running 时的下次轮询间隔
    ErrorCode   string             // failed 时
    ErrorMessage string
}

type AsyncStatus string
const (
    AsyncSubmitted AsyncStatus = "submitted"
    AsyncRunning   AsyncStatus = "running"
    AsyncSucceeded AsyncStatus = "succeeded"
    AsyncFailed    AsyncStatus = "failed"
)
```

`Registry`（按 filetype 路由）继续返回 `DocumentParser`；worker 层拿到 parser 后用 `if ap, ok := parser.(AsyncDocumentParser); ok` 检测是否走异步分支。

### 6.2 MinerU client

`adapters/parser/minerucloud/client.go`，封装 MinerU HTTP API：

```go
type Client struct { ... }
func (c *Client) RequestUploadURL(ctx context.Context, fileName string, sizeBytes int64, modelVersion string) (*UploadTicket, error)
func (c *Client) Upload(ctx context.Context, ticket UploadTicket, r io.Reader, contentType string) error
func (c *Client) Poll(ctx context.Context, externalJobID string) (*Result, error)
func (c *Client) Download(ctx context.Context, resultURL string) ([]byte, string, error)
```

- token 通过构造函数注入，不写入结构体日志字段、不进 error 明文（错误脱敏 Authorization）。
- 错误包含阶段 + HTTP status + 可重试标记，不含 token。

### 6.3 MinerU parser

`adapters/parser/minerucloud/parser.go` 实现 `DocumentParser`（`Supports("pdf")=true`，`Parse` 返回 `ErrUnsupportedFileType` 或委托异步流程的最小同步封装用于测试）和 `AsyncDocumentParser`：

- `Start`：校验 `pdf` → `rawStore.Open` 读取 PDF → 申请上传 URL → PUT 到 MinerU → 返回 `ExternalJobID` + payload（含 model_version、MinerU file 标识）。
- `Poll`：轮询 MinerU → running 返回 RetryAfter → failed 返回错误 → succeeded 下载结果（zip 则提取首个 `*.md`）→ 组装 `ParsedDocument{Markdown, Manifest}`，`Manifest.Parser="pdf"`。

`rawStore` 通过构造函数注入（`storage.RawDocumentStore`），MinerU client 也通过构造函数注入（便于 fake 测试）。

## 7. Parser Provider 能力域与凭据

### 7.1 设计决策

MinerU token 复用 `model_providers` 表存储（DB 零改动：`provider` 列无 CHECK，`provider="mineru"` 直接可存；`config jsonb` 放 base_url/timeout 等非敏感配置；`credentials_ciphertext` 放 token）。**不在 `models` 表建子行**（parser 无模型实例概念，`vlm`/`pipeline` 作为 provider config 或 parser 运行参数）。

障碍：现有 `ModelProviderService` 创建任意 provider 都强制 `registry.Factory(ModelTypeEmbedding, provider)` 成功（`application/service/model_provider.go:65,106,131,157`），MinerU 会被 embedding registry 拒绝。

### 7.2 引入 ParserProvider 能力域

解决方案：重构 Provider 管理使其支持多能力域。

**新增 port**（`ports/parserprovider/factory.go`）：

```go
// Factory 描述一个 parser provider 的凭据解码与 client 构造能力。
type Factory interface {
    Provider() string                              // "mineru"
    CredentialFields() []string                    // ["token"]
    DecodeProvider(ProviderDecodeInput) (config map[string]any, credentialsJSON []byte, err error)
    NewClient(ctx context.Context, ClientInput) (MinerUClient, error)
}
```

**新增 registry**（`adapters/parserprovider/registry.go`）：按 `provider` 字符串路由（parser provider 只有一个能力维度，不像 embedding 需要二元的 `modelType+provider`）。

**重构 `ModelProviderService`**：把「创建 provider 时强制校验 embedding registry」改为「按 provider 名路由到对应能力域 registry」——provider 名属于 embedding 注册集合则走 embedding registry，属于 parserprovider 注册集合则走 parserprovider registry，都不属于才报 `ErrUnsupportedProvider`。这样：

- 现有 embedding provider 管理链路（CRUD、连接测试、Web Console 表单）行为不变。
- MinerU provider 走同一套 CRUD（复用 `model_providers` 表、`CredentialCipher` 加密、scope/权限模型），但校验和 client 构造交给 parserprovider registry。
- HTTP 路由 `/admin/model-providers` 和 `/workspaces/:slug/model-providers` 复用；前端 MinerU 复用 Provider 管理页面但用独立表单（无 models 子表）。

### 7.3 凭据运行时选择

MinerU parser 在 `Start` 时需要一个可用的 MinerU provider 凭据。选择规则：

- 运行 worker 的 workspace 上下文中，查询 `scope='workspace' AND workspace_id=current AND provider='mineru' AND status='active'` 的 provider；若无，回退 `scope='platform' AND provider='mineru' AND status='active'`。
- 多个可用时，按 `created_at` 最新选择（MinerU token 无标准过期字段，简化处理；过期由 MinerU API 返回 401 触发 provider disable + warning）。
- 无可用 provider 时，`parse_start` 快速失败，document/job 记录 `missing_parser_provider` 错误。

token 解密只发生在 MinerU client 构造前的最小范围内，不进入 payload/日志/错误明文。

## 8. AssetResolver 与资产归档

### 8.1 AssetResolver 职责

`application/pipeline/asset_resolver.go`，输入 parser 产出的 raw Markdown + parser asset candidates，输出 normalized Markdown + asset rows + warnings。

处理范围：

- Markdown 图片 `![alt](url)`
- HTML `<img src="...">`
- `data:image/...;base64,...`
- zip 内相对路径图片（MinerU parser 解压后以 candidate 形式传入）
- 远程 `http/https` 图片 URL（走 `adapters/httpclient/ssrf.go`）

处理规则：

- 每张图计算 sha256 / mime / size。
- 每个 asset 用 UUIDv7。
- 写入对象存储 `assets/{workspace_id}/{document_id}/{revision_id}/{asset_id}.{ext}`。
- Markdown 中引用替换为 `public_url`。
- base64 图片正文不得进入 normalized Markdown。
- 远程下载必须走 SSRF-safe client（复用 `adapters/httpclient`，**不新建** `pipeline/ssrf_http_client.go`）。
- 超限（数量/大小）、MIME 拒绝、下载失败：保留原引用 + 记录 `ParseWarning`，不让整篇文档失败。

### 8.2 与 ParseStage / AssetStage 集成

现状 `AssetStage` 是空 stub（`Run(ctx, *model.Document)`）。v0.7.0 重构它：

- 签名改为 revision-scoped，与 `ParseStage` 一致：`Run(ctx, workspaceID, revisionID)`。
- ParseStage 在 `CompleteParse` 之后调用 AssetStage（或在 parse_poll 成功分支内串联）。
- AssetStage 内部：从 revision 取 normalized Markdown → AssetResolver 解析 → 删除该 revision 旧 assets → 写入新 assets → 更新 revision 的 normalized Markdown（引用已替换）+ 合并 warnings 到 ParseManifest。

资产清理按 **revision 级**（`document_assets.document_revision_id`），与「revision 不可变 + 按版本替换」一致：reparse 生成新 revision，新 revision 下 assets 独立。

### 8.3 `model.Asset` 对齐

给 `domain/model/asset.go` 的 `Asset` 补 `DocumentRevisionID uuid.UUID` 字段，与 `DocumentAssetRow` 对齐。

## 9. Worker 任务链调整

现有 `document_parse_start` / `document_parse_poll` / `document_index` 已存在。v0.7.0 调整 `parse_start` / `parse_poll` 的内部分支：

### 9.1 parse_start

```
读取 document/revision/job
若 revision 已 ready 或 document 已 published → 直接收尾
选择 MinerU provider 凭据（§7.3）
parser := registry.Get("pdf")
if async, ok := parser.(AsyncDocumentParser); ok:
    start := async.Start(ctx, AsyncParseInput{...})
    更新 job.external_job_id + payload
    入队 document_parse_poll（带 ExternalJobID + Payload）
else:
    走原同步 ParseStage（现有 5 个 parser 的路径，不变）
```

### 9.2 parse_poll

```
读取 document/revision/job（带 external_job_id + payload）
async.Poll(ctx, AsyncParsePollInput{...})
running → 更新 payload，延迟重入队 document_parse_poll
succeeded → revisions.CompleteParse(markdown, manifest) → AssetStage.Run → 入队 document_index
failed → job/revision 置 failed + 可诊断错误
```

### 9.3 幂等

- parse_start：若 revision 已有 external_job_id 且状态为 parsing，不重复 Start，只补发 poll。
- parse_poll：成功分支写 assets 前先清理同 revision 旧 assets，重试不产生重复资产。
- revision 已 ready/completed 的 poll 直接跳过。

## 11. ParseManifest 与 parser 白名单

`domain/model/parse_manifest.go:89-96` 的 `knownParser` 白名单加 `"pdf"`，否则 `Manifest.Validate` 会以「未知 parser」失败。PDF 的 `ParseManifest`：

- `Parser="pdf"`，`ParserVersion` 取 MinerU API 版本号。
- `Blocks[]`：MinerU Markdown 结构较平，PDF parser 负责生成 heading/paragraph/table 等 block + 字节 span + source anchor（页码锚点）。若 MinerU 不返回页码，anchor 用 document-level。
- `Warnings[]`：资产超限、图片下载失败等。

可选（若决定归档 MinerU 完整结果）：加 `parser_result_storage_key`，见 §15。

## 13. 安全限制

- MinerU token 只以 AES-GCM 密文存 `model_providers.credentials_ciphertext`，AAD 绑 provider ID（复用现有 `CredentialCipher`）。
- token 不进 YAML（长期）、日志、job payload、错误明文。
- S3 access/secret 只来自 YAML 配置，不写 DB/日志。
- 远程图片下载走 `adapters/httpclient/ssrf.go`（强制 HTTPS、拒绝 loopback/private/link-local/metadata、重定向全链路校验）。
- S3 key 不含未清理用户输入。
- 图片数量/大小/MIME 有上限，超限降级为 warning。
- raw Markdown 中的 base64 正文不进 normalized Markdown。

## 14. 测试策略

单元测试：

- S3 key builder 不受 path traversal 影响。
- S3 适配器 `Put/Open/Delete` 用 fake S3（`httptest` 或 SDK mock）；local AssetStore 参考 RawDocumentStore 的测试。
- MinerU client 用 `httptest` fake server 覆盖申请上传 URL / PUT / 轮询 running/success/failed / 下载 zip 与 markdown。
- MinerU parser 覆盖 Start 读取 PDF 上传、Poll 成功/失败/running、zip 提取 markdown、Supports。
- ParserProvider registry 与 MinerU Factory 的凭据解码/client 构造。
- AssetResolver 覆盖 markdown 图片 / HTML img / data URI / 远程 URL / zip 相对路径 / 超限 / MIME 拒绝 / 下载失败 warning。
- `knownParser` 白名单包含 pdf 后 manifest 校验通过。
- parse_start 重试不重复 Start；parse_poll 重跑不重复写 assets。

集成测试（临时 docker PostgreSQL + pgvector + Redis）：

- 端到端：创建 workspace/kb/document(revision kind=file, file_type=pdf) → 写入 MinerU provider 凭据 → fake MinerU server → 运行 parse_start + parse_poll 成功分支 → 断言 revision normalized_markdown 含 public URL、document_assets 记录正确、进入 document_index 到达 completed。
- 跨 workspace 隔离：parser provider 作用域、资产不串。
- 临时 RustFS/MinIO（可选 build tag）：S3 适配器 round-trip。
- 失败分支：MinerU 凭据缺失、MinerU 返回失败、资产超限。

不把真实 MinerU token 写入 fixture/CI；真实 MinerU 手动验收由操作者临时写入 provider 凭据。

## 15. 验收标准

- 上传 PDF 后，原始 PDF 出现在对象存储（或本地 raw dir）。
- `document_parse_start` 从存储读取 PDF 并上传到 MinerU 签名 URL。
- `document_parse_poll` 轮询成功后保存 raw Markdown key、normalized Markdown、assets。
- `document_revisions.normalized_markdown` 中图片引用为对象存储 public URL。
- `document_assets` 每个 asset 有 original_ref / storage_key / public_url / mime / sha256 / size / document_revision_id。
- 图片下载失败/超限/MIME 拒绝时保留原引用 + warning。
- PDF 经统一事实层到达 active Generation，可被 REST/Web/MCP `knowledge_search` 检索。
- worker 重试不产生重复 MinerU 提交或重复 asset。
- 解析失败保存可诊断错误。
- MinerU token 只通过 `model_providers` 写入，未进 YAML/日志/payload。
- Web Console 可上传 PDF、查看解析阶段进度、warning、失败诊断、资产预览。
- 远程资源下载通过 SSRF 防护。
- `go test ./...`、`go vet ./...`、`pnpm --dir web check/test/build` 通过。

## 16. 版本衔接

v0.7.0 之后的 v0.8.0（可靠性与运维）将处理：对象存储 GC（删除文档后的资产清理）、asynq 重试/退避/死信策略、reindex 与失败重试入口、可观测指标、批量导入限流、备份恢复演练。v0.7.0 的对象存储与 provider 凭据机制为这些铺路，但不在本版本实现。
