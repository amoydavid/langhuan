# `/setup` 表单宽度与密码输入焦点设计

## 目标

- 增加 `/setup` 初始化卡片的桌面端可用宽度，降低表单过窄的观感。
- 让用户在密码输入框中按 `Tab` 时直接进入下一个表单字段，不再停留在显示/隐藏密码按钮上。
- 统一所有 `PasswordInput` 的键盘行为，避免登录、邀请注册、成员密码重置和初始化页面表现不同。

## 方案选择

采用以下实现：

1. 将 `/setup` 卡片的最大宽度从 Tailwind `max-w-xl` 调整为 `max-w-2xl`。卡片继续保留 `w-full`，因此小屏仍随容器自适应，不引入固定宽度或横向滚动。
2. 在共享 `PasswordInput` 的显示/隐藏按钮上设置 `tabIndex={-1}`。按钮仍然是带无障碍名称的原生 `button`，保留鼠标和触屏点击能力，但不参与顺序键盘导航。

未采用的方案：

- 只在 `/setup` 增加控制参数：会让同一个密码控件在不同页面产生不同的 Tab 行为。
- 保留显示/隐藏按钮在 Tab 顺序中：键盘可直接访问该操作，但不符合本次要求的连续表单填写路径。
- 把初始化表单改成多列：邮箱、昵称和两次密码输入仍适合单列阅读；本次只增加容器留白，不改变信息结构。

## 交互与边界

顺序键盘导航保持 DOM 中的表单字段顺序。初始化页面的主要路径为：邮箱 → 昵称 → 密码 → 确认密码 → 完成初始化。两个密码可见性按钮均被跳过。`Shift+Tab` 同样按表单字段顺序反向移动，不进入可见性按钮。

本次不改变密码校验、提交逻辑、API 请求、认证路由或其他页面布局。

## 验证

- 先为 `PasswordInput` 增加回归测试，证明当前显示/隐藏按钮仍在 Tab 顺序中，并观察测试失败。
- 实现后验证按钮可点击切换密码可见性，同时具有 `tabindex="-1"`。
- 在 `SetupForm` 测试中验证从密码输入按 `Tab` 后焦点进入确认密码输入框。
- 运行相关 Vitest、`pnpm --dir web check`、`pnpm --dir web test`、`pnpm --dir web build` 和 `git diff --check`。
