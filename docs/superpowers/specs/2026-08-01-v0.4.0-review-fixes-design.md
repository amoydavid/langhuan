# v0.4.0 评审问题修复设计

## 目标

修复 v0.4.0 评审确认的八类问题，同时保持知识事实模型 v2 的 Generation、Workspace transaction、不可变 Revision 和可重建 RetrievalEntry 边界。

## 设计决策

1. 删除旧的 `PATCH /knowledge-bases/:id/embedding-model`、对应 Binder 方法和 Web Console 对话框。模型变更只允许通过现有 IndexGeneration 创建、后台构建和原子激活流程完成，不恢复 `knowledge_bases.embedding_model_id`。
2. 修复普通 Chunker 的超长 heading 窗口推进，任何窗口都只能从已输出区间内按 overlap 回退，不能跨过未输出字符。将 standard Chunker 合同版本从 1 提升到 2，并把版本常量放到 pipeline 包供 Generation 和 ChunkStage 共用。
3. v2 文件导入的初始任务入队失败由 `DocumentIngestStore` 在 Workspace transaction 中同时标记 Document、DocumentRevision 和 Job 失败；移除 v1 Repository fallback 及不再使用的 v1 Document/Chunk/Job 方法。
4. `vector_top_k` 与 `keyword_top_k` 的 Generation 配置和单次搜索覆盖值统一限制在 1..1000；`final_top_k` 保持 1..50，并使用具名常量。
5. HNSW 集成验收以单个 table-driven 测试覆盖 798、1024、2048、3584 四种固定 SQL，关闭顺序扫描后断言查询计划包含对应 HNSW 索引名。
6. Generation 构建是全有或全无，删除无稳定语义的 `failed_count`。新增迁移删除列，down 只负责恢复非空默认零列；同步 Row、Domain、DTO、SQL 和设计文档。
7. `domain/value.ChunkingConfig` 移除 JSON tag。HTTP 层使用自己的 request DTO，显式转换到领域值对象。
8. FAQ create/update 对非法 JSON 统一返回固定的 `validation_error` 文案，不暴露 `encoding/json` 原始错误。

## 错误与事务

- 初始任务入队失败必须保留原始对象以便诊断/恢复，但数据库中的 Document、Revision、Job 必须在同一 Workspace transaction 进入 failed；若失败状态持久化也失败，用 `errors.Join` 同时保留队列错误和持久化错误。
- TopK 超限返回 `domainerrors.ErrValidation`，HTTP 映射为 400。
- 删除旧换模入口后，路由返回 404；前端不再展示会产生错误语义的操作。

## 测试

- 每个行为修改先增加失败测试并观察预期失败，再写最小实现。
- 数据库行为使用 `integration` build tag 和 testcontainers 临时 pgvector 数据库。
- 完成后执行 Go 单元/集成测试、vet、前端 check/test/build 与 `git diff --check`。
