# 琅嬛 v0.3.1 模型配置与选择设计规格

> 状态：v0.3.1 已于 2026-07-30 完成实现；后端、真实 PostgreSQL/Gin/Auth E2E、Web Console 测试与构建均已通过。

## 1. 背景

v0.3.0 已完成 Markdown、TXT、CSV、XLSX、DOCX 的本地解析、version 1 parse manifest 与结构化分块。当前知识库仍由调用方直接填写 `embedding_dimension`，Web Console 默认值是 1536；但数据库只为 798、1024、2048、3584 四种维度预建了 pgvector HNSW 部分索引。v0.4.0 如果直接在这个基础上接入 Embedding，会同时遇到以下问题：

- API key、Endpoint、Provider 参数没有安全、可管理的持久化位置。
- 不同 Workspace 无法注册自己的模型连接，也无法使用平台统一提供的共享连接。
- 知识库只记录维度，不记录实际使用的模型，无法追踪向量来自哪个 Provider 和模型。
- 维度允许任意正整数，可能写入没有 HNSW 索引的向量。
- Provider 参数差异较大，单一无类型 JSON 会把错误推迟到运行时。

因此在 v0.4.0 向量化之前插入 v0.3.1，先交付 Provider 连接管理、Embedding 模型注册、连接测试和知识库显式选择，形成稳定的模型配置合同。

本规格参考 Eino 的组件边界与官方 Embedding 集成：

- Document Loader 负责从文件、URL 等来源加载并标准化文档，不属于模型配置。琅嬛现有 `DocumentParser -> ParseManifest -> Chunk` 链路不因 v0.3.1 改造为 Eino Loader。
- ChatModel 展示了 Eino 通过统一接口承载多个原生 Provider 的扩展方式，但琅嬛仍不生成 LLM 答案，v0.3.1 不开放 LLM/Rerank 能力。
- Embedding Provider 使用各自的 Eino 原生组件，而不是把供应商名称仅作为 OpenAI-compatible UI 预设。

## 2. 已确认的产品决策

1. v0.3.1 只实现 Embedding 配置、测试和选择，不实现 LLM、Rerank 的 Adapter、API 或页面。
2. 数据模型允许未来增加 `llm`、`rerank`，但当前 Service 只接受 `embedding`。
3. 配置采用 `model_providers + models` 两层结构：连接、端点和凭证属于 Provider；具体模型和维度属于 Model。
4. Provider 有两种作用域：平台共享与 Workspace 自有。Workspace 可见“平台共享 + 当前 Workspace 自有”。
5. 每个知识库显式保存一个 `embedding_model_id`，不使用 Workspace 动态默认值。
6. Provider 使用 Eino 原生协议与组件。v0.3.1 支持 OpenAI、ARK、Ollama、DashScope、TencentCloud。
7. 千帆暂不支持：当前 Eino 千帆组件及底层 SDK 在请求时读取进程级全局凭证，不能安全承载多 Workspace 的不同账号。
8. 数据库不对 `provider` 建枚举 CHECK。Provider 合法性由 application Registry 校验，未来新增 Provider 不需要修改表结构。
9. Embedding 维度只允许当前已有 HNSW 索引的 798、1024、2048、3584；UI 默认 1024。
10. 当前数据库没有知识库业务数据，迁移不做回填、占位模型或同步迁移，直接用模型引用替代知识库维度字段。
11. Provider 凭证使用 AES-256-GCM 加密，单一密钥直接配置在未提交的 `config.yaml` 中。
12. Ollama 只能由 platform_admin 创建为平台共享 Provider；Workspace 自有 Provider 只能访问经过 SSRF 校验的公网 HTTPS 地址。

## 3. 目标

v0.3.1 交付以下闭环：

```text
平台管理员 / Workspace 管理员
  -> 配置 Provider 连接与加密凭证
  -> 在 Provider 下注册 Embedding 模型
  -> 使用固定测试文本验证连接与实际维度
  -> member+ 创建知识库时显式选择可见模型
  -> 知识库持久化 embedding_model_id
  -> v0.4.0 按 model_id 解析真实 Embedder
```

具体目标：

- 平台共享模型对所有 Workspace 可见，但只有 platform_admin 能修改。
- Workspace 自有模型只对所属 Workspace 可见，由 admin/owner 管理。
- member 可以读取可见模型，并在创建知识库时选择。
- 凭证明文不进入数据库、响应、日志或前端 Query 缓存。
- Provider config、credentials、Model parameters 均使用 typed struct 校验。
- 连接测试真实构造 Eino Embedder，并验证返回向量维度。
- 知识库不能选择不可见、已停用、非 Embedding 或不受支持维度的模型。
- 数据模型能在后续增加 LLM/Rerank，而不重复存储同一 Provider 凭证。

## 4. 非目标

v0.3.1 明确不做：

- 批量向量化、pgvector/FTS 写入或索引生命周期。
- REST 检索、MCP 检索工具、RRF 或 rerank。
- LLM/ChatModel 的配置页面、调用或答案生成。
- Rerank Adapter。
- 千帆 Adapter。
- YAML 模型目录或启动同步。
- 自动模型发现或拉取供应商模型列表。
- 自动 fallback、按请求覆盖模型或 Workspace 动态默认模型。
- 自动凭证 key 轮换或历史密文批量重加密。
- 更换 Embedding 模型后的重建索引；v0.4.0 接入索引时再把切换升级为显式 reindex 流程。
- PDF/MinerU、图片资产归档或对象存储。
- 用 Eino Document Loader 替换当前本地 parser。

## 5. 方案比较与选择

### 5.1 单张 `models` 表

每条模型同时保存 Provider、Endpoint、凭证和模型参数。

优点：表少，首版 CRUD 直接。

缺点：一个 OpenAI/ARK/DashScope 账号注册多个 Embedding、LLM、Rerank 模型时会重复保存凭证；凭证轮换需要更新多行；连接作用域和模型作用域容易漂移。

结论：不采用。

### 5.2 `model_providers + models` 两层结构

Provider 表示一套真实连接、作用域与凭证；Model 表示该连接下的模型实例和类型专属参数。

优点：

- 凭证只保存一次，轮换后同一 Provider 下的模型共同生效。
- 平台共享/Workspace 自有的隔离只定义一次。
- Provider 连接参数和模型推理参数职责清晰。
- 后续增加 LLM/Rerank 不需要重构凭证存储。

缺点：读取模型时需要 JOIN Provider；删除顺序与引用约束更严格。

结论：采用。

### 5.3 每个 Provider 一套表

为 OpenAI、ARK、Ollama 等分别建立连接表和模型表。

优点：数据库字段类型最强。

缺点：五套迁移、Row、Repository 与 JOIN；新增 Provider 必须修改数据库，和本版本希望通过 Registry 扩展 Provider 的目标冲突。

结论：不采用。

## 6. 核心概念与不变量

### 6.1 ModelProvider

`ModelProvider` 表示可建立远程或本地模型客户端的一套连接：

- `scope=platform`：平台共享，`workspace_id` 必须为空。
- `scope=workspace`：Workspace 自有，`workspace_id` 必须存在。
- `provider`：Registry key，例如 `openai`、`ark`。
- `config`：非敏感 typed 连接参数。
- `credentials_ciphertext`：完整凭证 JSON 的 AES-GCM 密文。
- `status`：`active` 或 `disabled`。

Provider 的 `name` 是稳定机器标识，创建后不可修改；`display_name` 是可编辑展示名称。

Provider 与 Model 的文本字段统一执行 application 校验：

- `name`：转小写后匹配 `^[a-z][a-z0-9_-]{0,63}$`。
- `display_name`：去除首尾空白后不超过 255 个 Unicode 字符；空值回退为 `name`。
- `description`：不超过 2000 个 Unicode 字符。
- `provider`：转小写后不超过 64 个 ASCII 字符，并且必须命中 Registry。
- `model_name`：去除首尾空白后非空，不超过 255 个 Unicode 字符。

### 6.2 Model

`Model` 表示 Provider 下的一个可选模型：

- `type`：`embedding | llm | rerank`。
- `model_name`：发送给供应商的真实模型名、部署名或 endpoint ID。
- `dimensions`：仅 Embedding 使用。
- `parameters`：模型级 typed 参数。
- `status`：`active` 或 `disabled`。

v0.3.1 只允许通过 API 创建 `type=embedding`。

### 6.3 KnowledgeBase 绑定

每个知识库必须显式引用一个 Model：

```text
KnowledgeBase.embedding_model_id -> models.id
```

绑定必须同时满足：

- Model 类型是 `embedding`。
- Model 与 Provider 都是 `active`。
- Provider 是平台共享，或 Provider 的 `workspace_id` 等于知识库的 `workspace_id`。
- Model 维度属于 798、1024、2048、3584。

不进行自动 fallback。已有绑定在 Provider/Model 停用后保留，但显示为不可用。

## 8. 数据库设计

迁移名称：

```text
000004_model_configuration.up.sql
000004_model_configuration.down.sql
```

### 8.1 `model_providers`

```sql
CREATE TABLE IF NOT EXISTS model_providers (
    id                     uuid PRIMARY KEY DEFAULT gen_random_uuid(),

    scope                  text NOT NULL,
    workspace_id           uuid REFERENCES workspaces(id) ON DELETE CASCADE,

    name                   text NOT NULL,
    display_name           text NOT NULL DEFAULT '',
    description            text NOT NULL DEFAULT '',
    provider               text NOT NULL,

    config                 jsonb NOT NULL DEFAULT '{}'::jsonb,
    credentials_ciphertext bytea,

    status                 text NOT NULL DEFAULT 'active',
    created_by             uuid REFERENCES users(id) ON DELETE SET NULL,
    created_at             timestamptz NOT NULL DEFAULT now(),
    updated_at             timestamptz NOT NULL DEFAULT now(),

    CONSTRAINT model_providers_scope_check
        CHECK (scope IN ('platform', 'workspace')),

    CONSTRAINT model_providers_workspace_check
        CHECK (
            (scope = 'platform' AND workspace_id IS NULL)
            OR
            (scope = 'workspace' AND workspace_id IS NOT NULL)
        ),

    CONSTRAINT model_providers_status_check
        CHECK (status IN ('active', 'disabled'))
);

CREATE UNIQUE INDEX uq_model_providers_platform_name
    ON model_providers (lower(name))
    WHERE scope = 'platform';

CREATE UNIQUE INDEX uq_model_providers_workspace_name
    ON model_providers (workspace_id, lower(name))
    WHERE scope = 'workspace';

CREATE INDEX idx_model_providers_workspace_visibility
    ON model_providers (workspace_id, status, provider);

CREATE INDEX idx_model_providers_platform_visibility
    ON model_providers (status, provider)
    WHERE scope = 'platform';
```

不增加 `provider IN (...)` CHECK。数据库只保存稳定的小写 Registry key；未注册 key 不能通过 Service 创建。

### 8.2 `models`

```sql
CREATE TABLE IF NOT EXISTS models (
    id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    provider_id  uuid NOT NULL
                 REFERENCES model_providers(id) ON DELETE RESTRICT,

    name         text NOT NULL,
    display_name text NOT NULL DEFAULT '',
    description  text NOT NULL DEFAULT '',

    type         text NOT NULL,
    model_name   text NOT NULL,
    dimensions   integer,
    parameters   jsonb NOT NULL DEFAULT '{}'::jsonb,

    status       text NOT NULL DEFAULT 'active',
    created_by   uuid REFERENCES users(id) ON DELETE SET NULL,
    created_at   timestamptz NOT NULL DEFAULT now(),
    updated_at   timestamptz NOT NULL DEFAULT now(),

    CONSTRAINT models_type_check
        CHECK (type IN ('embedding', 'llm', 'rerank')),

    CONSTRAINT models_dimensions_check
        CHECK (
            (
                type = 'embedding'
                AND dimensions IN (798, 1024, 2048, 3584)
            )
            OR
            (
                type IN ('llm', 'rerank')
                AND dimensions IS NULL
            )
        ),

    CONSTRAINT models_status_check
        CHECK (status IN ('active', 'disabled'))
);

CREATE UNIQUE INDEX uq_models_provider_type_name
    ON models (provider_id, type, lower(name));

CREATE INDEX idx_models_provider_type_status
    ON models (provider_id, type, status);
```

### 8.3 `knowledge_bases`

当前没有需要保留的知识库数据，因此 up migration 直接替换字段：

```sql
ALTER TABLE knowledge_bases
    DROP COLUMN IF EXISTS embedding_dimension;

ALTER TABLE knowledge_bases
    ADD COLUMN embedding_model_id uuid NOT NULL
    REFERENCES models(id) ON DELETE RESTRICT;

CREATE INDEX idx_knowledge_bases_embedding_model_id
    ON knowledge_bases(embedding_model_id);
```

不创建 legacy row、不回填默认 Provider、不生成占位模型，也不保留维度快照。模型的 `dimensions` 是唯一真实来源。

down migration 在删除引用前从 Model 恢复维度，以保证将来有数据时也能正确降级：

```sql
ALTER TABLE knowledge_bases
    ADD COLUMN embedding_dimension integer;

UPDATE knowledge_bases AS kb
SET embedding_dimension = m.dimensions
FROM models AS m
WHERE kb.embedding_model_id = m.id;

ALTER TABLE knowledge_bases
    ALTER COLUMN embedding_dimension SET NOT NULL,
    ALTER COLUMN embedding_dimension SET DEFAULT 1024;

ALTER TABLE knowledge_bases
    ADD CONSTRAINT knowledge_bases_embedding_dimension_check
    CHECK (embedding_dimension > 0);

DROP INDEX IF EXISTS idx_knowledge_bases_embedding_model_id;

ALTER TABLE knowledge_bases
    DROP COLUMN embedding_model_id;
```

随后按引用逆序删除 `models`、`model_providers`。

### 8.4 Row 与 Repository

- `ModelProviderRow`、`ModelRow` 放在 `internal/infrastructure/db`，使用 GORM tag。
- `config`、`parameters` 使用现有 `JSONMap`。
- 领域模型不带 JSON/GORM tag。
- Provider 与 Model 分别使用聚焦的 repository 文件，不放进通用 `repository.go`。
- 所有查询使用 `WithContext(ctx)`。
- Workspace 可见模型查询必须 JOIN Provider，并显式使用：

```sql
provider.scope = 'platform'
OR provider.workspace_id = :workspace_id
```

- 任何通过 Workspace 路由进行的修改还必须限定 `provider.scope='workspace' AND provider.workspace_id=:workspace_id`。
- `gorm.ErrRecordNotFound` 在 Repository 层映射为领域 `ErrNotFound`。
- 知识库创建时的 Model 可见性验证和 KnowledgeBase 写入位于同一事务语义中，防止检查与写入之间状态漂移。

## 9. Provider typed config 合同

### 9.1 公共规则

Registry 使用组合键：

```text
(model_type, provider)
```

v0.3.1 注册：

```text
(embedding, openai)
(embedding, ark)
(embedding, ollama)
(embedding, dashscope)
(embedding, tencentcloud)
```

每个注册项负责：

- 解码 Provider config。
- 解码 credentials。
- 解码 Model parameters。
- 校验字段组合与 scope。
- 构造 Eino Embedder。
- 包装成琅嬛 `EmbeddingClient`。
- 清洗供应商错误。

数据库 JSONB 只是一种持久化编码。原始 `map[string]any` 不能进入 application 业务逻辑；codec 必须转换为 Provider 专属 Go struct。

### 9.2 OpenAI

Provider config：

```text
mode               standard | azure
base_url           standard 可选，azure 必填
api_version        azure 必填，standard 必须为空
timeout_seconds    1..600
```

Credentials：

```text
api_key            必填
custom_headers     map[string]string，可选，整体加密
```

Model：

```text
model_name
dimensions         798 | 1024 | 2048 | 3584
batch_size         1..200，默认 32
```

标准模式允许 OpenAI-compatible 公网 Base URL。Adapter 通过自定义 `http.Client` 注入安全 Transport 和允许的自定义 headers；输出固定使用 float 编码。

### 9.3 ARK

Provider config：

```text
base_url           可选，默认 Eino 官方值
region             可选，默认 cn-beijing
auth_mode          api_key | ak_sk
timeout_seconds    1..600
retry_times        0..5，默认 2
```

Credentials：

```text
auth_mode=api_key  -> api_key
auth_mode=ak_sk    -> access_key + secret_key
```

Model：

```text
model_name         ARK endpoint ID
dimensions         四种受支持维度之一
batch_size         1..200，默认 32
```

v0.3.1 固定使用文本 Embedding API，不开放多模态 `APIType` 或 `MaxConcurrentRequests`。

### 9.4 Ollama

Provider config：

```text
base_url           可选，默认 http://localhost:11434
timeout_seconds    1..600
```

Credentials：无。

Model：

```text
model_name
dimensions         四种受支持维度之一
batch_size         1..200，默认 32
truncate           bool，可选
keep_alive_seconds 0..86400，可选
```

不开放 Eino Ollama 的 `Options map[string]any`。Ollama Provider 只允许 `scope=platform`。

### 9.5 DashScope

Provider config：

```text
timeout_seconds    1..600
```

Credentials：

```text
api_key            必填
```

Model：

```text
model_name
dimensions         固定 1024
batch_size         1..200，默认 32
```

Eino DashScope 当前可调维度与琅嬛 HNSW 索引的交集只有 1024，因此 UI 与 Service 都不接受其它维度。

### 9.6 TencentCloud

Provider config：

```text
region             必填，例如 ap-guangzhou
```

Credentials：

```text
secret_id          必填
secret_key         必填
```

Model：

```text
model_name         固定 hunyuan-embedding
dimensions         固定 1024
batch_size         固定由 Eino 组件处理，不向用户开放
```

Eino TencentCloud 组件不接受外部模型名，并在内部按供应商限制自动以 200 条为一批处理；界面不提供无效的可编辑字段。

### 9.7 千帆延期原因

Eino 千帆组件要求通过 `GetQianfanSingletonConfig()` 设置 AccessKey/SecretKey。其底层 SDK 的 Requestor 在真实请求阶段继续读取 `GetConfig()`，不是在 Embedder 构造时复制出实例级凭证。

这意味着两个 Workspace 并发使用不同千帆账号时可能串用凭证。全局互斥锁虽然能强制串行，但会把所有 Workspace 的千帆流量变成一个全局临界区，也会留下 SDK 内部异步行为难以审计的问题。因此 v0.3.1 对 `provider=qianfan` 返回 `unsupported_provider`。

重新接入需要满足以下任一条件：

- Eino/千帆 SDK 提供实例级凭证 Client；或
- 单独设计并批准无全局状态的千帆原生 Adapter。

## 10. 凭证加密

### 10.1 配置

`config.example.yaml` 增加：

```yaml
credentials:
  # 生成命令：openssl rand -base64 32
  # 将输出复制到实际 config.yaml，不要包含行尾换行；不要提交真实值。
  encryption_key: ""
```

实际 `config.yaml` 已被 `.gitignore` 排除，可以保存真实 key。项目不提供环境变量回退。

配置校验：

- 必须是合法 Base64。
- 解码后必须正好为 32 字节。
- v0.3.1 运行时启动时为空或非法则直接失败。
- 错误只描述配置项无效，不输出原值。

### 10.2 密文格式

使用标准库 AES-256-GCM：

```text
[1 byte format version][12 byte random nonce][ciphertext + GCM tag]
```

- 每次加密使用 `crypto/rand` 生成新 nonce。
- 同一凭证重复保存必须产生不同密文。
- Additional Authenticated Data 使用 `model-provider:<provider_uuid>`，防止把一行密文复制到另一 Provider 后仍能解密。
- 明文是 Provider 专属 credentials struct 的 JSON 编码。
- Repository 只保存/读取密文；加解密由 application 使用注入的 CredentialCipher 完成。
- 解密失败映射为内部凭证错误，不把 GCM 或 JSON 细节返回调用方。

v0.3.1 只有一把 key，不保存 `credentials_key_id`，不支持在线轮换。未来换 key 必须先用旧 key 解密全部凭证、用新 key 重加密并原子更新，再修改配置。

## 13. 连接测试

测试放在 Model 层，因为 Embedding 调用必须同时知道 Provider 连接、`model_name` 和声明维度。

固定测试文本：

```text
langhuan embedding connection test
```

流程：

1. 按路由作用域和角色读取 Model/Provider。
2. 解密 Provider credentials。
3. Registry 查找 `(embedding, provider)`。
4. typed codec 解码 config、credentials、parameters。
5. 使用请求 Context 和配置超时构造 Eino Embedder。
6. 请求一条向量。
7. 验证数量、非空、有限数值和维度。
8. 返回结果与耗时，不保存输入或向量。

成功响应：

```json
{
  "ok": true,
  "dimensions": 1024,
  "duration_ms": 183
}
```

失败响应只包含稳定错误码与安全描述。管理权限持有者可以测试 disabled Model/Provider，以便修复配置后再启用；disabled 记录仍不能被新知识库选择。

## 14. 生命周期与删除

Provider/Model 状态只使用：

```text
active
disabled
```

不使用 `deleted_at`：

- Provider 下仍有 Model 时删除返回 409 `provider_in_use`。
- Model 被知识库引用时删除返回 409 `model_in_use`。
- 未引用记录物理删除。
- 需要保留但禁止使用的记录改为 disabled。

停用 Provider 会让其下全部 Model 不可被新知识库选择。已有知识库保留引用并显示不可用，不自动切换。

Provider 的 Endpoint、凭证和连接参数允许更新，并影响其下全部 Model。Model 的展示信息、批量参数和状态允许更新；语义字段在被引用后不可原地修改。

## 15. 网络与 SSRF 安全

### 15.1 Workspace 自有 Provider

- 只允许公网 HTTPS endpoint。
- 拒绝 URL 用户信息、fragment、非 HTTP(S) scheme 和空 Host。
- DNS 解析后拒绝 loopback、私网、链路本地、组播、保留地址和云元数据地址。
- 每次重定向都重新校验目标，限制重定向次数。
- 连接时固定已校验地址，防止 DNS rebinding。
- 自定义 HTTP client 必须透传 Context 并设置超时。
- 自定义 headers 禁止覆盖 `Host`、`Content-Length`、`Connection`、`Proxy-Authorization` 等路由或 hop-by-hop 字段。

ARK、DashScope、TencentCloud 使用官方端点时不开放任意私网覆盖。OpenAI standard 模式可以使用经过校验的公网 OpenAI-compatible Base URL。

### 15.2 Ollama

- Ollama 只允许 `scope=platform`。
- platform_admin 可以配置 HTTP、本机或私网地址。
- Workspace 路由创建 `provider=ollama` 返回 400 `provider_scope_not_allowed`。

平台管理员属于受信任运维边界；这一例外不能扩展到其它 Workspace 自定义 URL。

## 17. 错误处理

稳定领域/API 错误码：

```text
unsupported_provider
provider_scope_not_allowed
invalid_provider_config
credentials_required
unsupported_model_type
unsupported_embedding_dimension
model_not_visible
model_disabled
provider_disabled
dimension_mismatch
connection_test_failed
authentication_failed
endpoint_unreachable
request_timeout
rate_limited
provider_rejected
invalid_embedding_response
immutable_model_field
model_in_use
provider_in_use
```

HTTP 映射：

- 参数、Provider、类型、维度错误：400。
- 未登录：401；Workspace 角色不足：403。
- 跨 Workspace、通过错误作用域路由操作共享记录：404。
- 引用冲突、不可变字段：409。
- 供应商认证失败或返回非法向量：422。
- 供应商不可达/拒绝：502。
- 供应商超时：504。
- 凭证解密失败属于服务端配置/数据错误，对外统一返回 500 `internal_error`；日志只记录 `credential_decryption_failed` 分类和 Provider ID。

Adapter 不把供应商原始响应体直接上抛到 HTTP。每层只包一次上下文，并保留 error chain。

结构化日志允许记录：

```text
workspace_id
provider_id
model_id
provider
duration_ms
error_class
```

不得记录请求头、凭证、供应商原始响应体、测试向量或用户文档内容。

```text
  -> Model 被知识库引用后无法删除
```

真实 Provider 凭证只用于人工验收，不进入仓库或 CI。普通 E2E 注入 fake Registry/Factory，仍使用真实 PostgreSQL、Gin、认证与 Repository。

## 19. 验收标准

v0.3.1 完成需要满足：

1. platform_admin 能管理平台共享 Provider/Embedding Model。
2. Workspace admin/owner 能管理自有 Provider/Embedding Model，member 只能查看。
3. Workspace 只能看到平台共享与自身配置，跨 Workspace 读取/修改统一 404。
4. OpenAI、ARK、Ollama、DashScope、TencentCloud typed config 与 Eino Factory 均可构造并测试。
5. `qianfan` 明确拒绝，不存在全局凭证写入路径。
6. Ollama 只能创建为平台共享 Provider。
7. 数据库中 Provider 凭证是 AES-GCM 密文；API、日志和前端缓存没有明文。
8. `config.example.yaml` 给出 `openssl rand -base64 32` 生成命令，真实配置校验 32-byte key。
9. Model 维度只允许 798、1024、2048、3584；Web 默认 1024。
10. 知识库创建必须显式选择可见 active Embedding Model，不再接受 `embedding_dimension`。
11. 被知识库引用的 Model 不能删除或修改语义字段，不发生自动 fallback。
12. v0.3.1 不调用实际文档 Embedding，不写入 `chunk_embeddings`。

## 20. 与后续版本衔接

### v0.4.0

- `document_index` 根据 `KnowledgeBase.embedding_model_id` 构造 Embedder。
- 使用 Model 的 `batch_size`、`dimensions` 和 Provider 超时。
- 调用前增加输入长度保护、并发限制与重试策略。
- 写入 pgvector 与 FTS。
- 向量 metadata 记录 `model_id`、`provider_id`、`model_name` 和维度，支持判断索引是否过期。
- 更换知识库模型改为显式 reindex，不允许直接留下旧向量。

### 后续 LLM/Rerank

- 复用 `model_providers` 的作用域、凭证和连接配置。
- 在 Registry 增加 `(llm, provider)` 或 `(rerank, provider)`。
- 为新类型增加 typed Model parameters、API 与选择位置。
- 不把 LLM/Rerank 字段提前塞进 KnowledgeBase；只有出现真实消费方时再确定选择粒度。

### v0.8.0 MinerU

MinerU 等服务端凭证可以复用本规格的 CredentialCipher，但 Provider 表是否承载解析服务凭证需要届时单独设计；v0.3.1 不把非模型服务塞进 `model_providers`。
