## 1. 目标与范围

为琅嬛补齐 `web` Document 契约对应的实际能力：在**知识库内部**引入"网站内容源"实体——一个 KB 可挂多个网站源，每个源按配置（受限爬取 / sitemap / 显式 URL 列表）抓取网页，页面作为 `kind='web'` 文档与上传文件混居同一知识库，走同一 parse/chunk/index 管线与 Generation 快照机制，可被同一次检索命中。每个源是独立的管理单元：有自己的配置、同步调度、增量游标与失败状态，可单独重跑、改配置、启停、删除；页面文档记录来源（溯源）。

本版本覆盖：

- 知识库内多内容源（`kb_sources`）：新增"网站源"实体，一库多源、与上传文件混装；
- 三种导入模式：`crawl`（种子 URL 受限爬取）、`sitemap`（sitemap.xml 发现）、`urls`（显式 URL 列表，可增删）；
- 可插拔抓取引擎：内建 `http`（SSRF-safe 静态抓取）、`render`（远程 CDP 无头浏览器）、`firecrawl`、`jina`（托管抓取 provider）；
- `engine: auto` 渐进升级：静态抓取命中 JS-shell 特征时自动升级到已配置的高级引擎；
- 参数化正文抽取：go-readability + html-to-markdown，含整页回退；
- 三级增量检测：sitemap `lastmod` → HTTP 条件请求（ETag/Last-Modified）→ `content_hash` 兜底；
- robots.txt 遵守（默认开启，可关）、per-host 限速、标识性 User-Agent；
- Web Console 内容「Web」子 tab 的抓取请求管理界面（请求列表 → 源详情下钻，与 FAQ 的"列表 → 详情"同构）与 MCP/REST 的源级管理入口。

本版本不覆盖：

- 内嵌/打包任何浏览器二进制（render 引擎只接受外部 CDP endpoint）；
- firecrawl 自托管栈的一等集成（允许自定义 endpoint 连用，不打包其容器）；
- 登录态/验证码站点、非 HTML 资源（PDF/DOC 链接记 warning 跳过）、站点内搜索；
- firecrawl `/crawl`、`/map` 整站托管发现（发现与 diff 始终在琅嬛侧）；
- 飞书源迁移进 `kb_sources` 模型（飞书保持现有 KB 级机制不动，统一留待后续版本）；
- 飞书 KB 挂网站源（飞书库的文档集由飞书同步全权管理，放开混装与飞书迁移一并再议）。

## 3. 核心建模决策

### 3.1 知识库是检索域，源是摄取通道

- **KB 不新增类型**：`knowledge_bases.source_type` 保持 `upload|feishu_drive|feishu_wiki`，CHECK 不放宽。创建表单的"内容来源"零改动。
- **新增 `kb_sources` 实体**：挂在 KB 下的一行 = 一个内容源（本版仅 `kind='web'` 网站源；未来飞书迁入同一实体）。源持有自己的配置、调度状态与删除策略。
- **页面文档混居**：源抓到的页面写成 `Document{kind:'web', source_type:'web', source_uri: <规范化 URL>, external_id: <规范化 URL>}`，落在上传文件同一个 KB 里，进同一 active Generation、同一索引。检索调用方传 KB 即同时罩住文件与网页——这就是用户裁决要解决的多库召回问题：站点级建模会把同一份知识人为拆进多个检索域，跨库合并成本转嫁给调用方；混装后一次检索覆盖全部。
- **溯源**：`documents` 新增可空列 `kb_source_id`——源产生的页面指向源行；上传文档为 NULL。Console 据此展示"这份内容来自哪个源"，并支持按源统计/清理。
- **连接只承载凭证**：`workspace_source_connections` 用途不变（`provider ∈ {feishu, firecrawl, jina, browser}`）；`browser` 连接保存 CDP `endpoint_url`（config，非敏感）+ 可选 token（密文）；`firecrawl`/`jina` 必须提供 api_key（密文）。源通过 `connection_id` 引用同 workspace 的 active connection（`http` 引擎无需连接）；一个源最多引用一个 connection。

### 3.2 `kb_sources` 实体与同步状态

```text
kb_sources (
  id uuid PK,
  workspace_id uuid NOT NULL,
  kb_id uuid NOT NULL REFERENCES knowledge_bases,
  kind text NOT NULL DEFAULT 'web'            -- 本版仅 'web'，CHECK 约束
  name text NOT NULL,                          -- 展示名，如 "产品文档站"
  status text NOT NULL DEFAULT 'active',       -- active | disabled
  config jsonb NOT NULL,                       -- §4.1（mode/fetch/extract/crawl/urls/sync/on_delete）
  sync_cursor jsonb NOT NULL DEFAULT '{}',     -- 稳定 watermark（原 KB 级 sync_cursor 语义）
  next_sync_at timestamptz,
  sync_requested_force boolean NOT NULL DEFAULT false,
  sync_last_result jsonb NOT NULL DEFAULT '{}',
  created_at / updated_at / deleted_at
)
```

- 编排键从 KB 变为源：`SourceSyncService` 的 diff/cursor/force latch/on_delete/source_cleanup 全部以源为单位执行；`on_delete` 从 KB 配置移到源配置。
- 调度：`next_sync_at` 推进与 connection 限流按源执行（§9.1）；进程级天花板 `web_source.max_sources_per_kb` 限制单 KB 源数。
- 纯函数层（`diff()`、URL 去重、normalized token 规则、`RetryRequired` 分类）零改动，仅输入从"KB 的期望全集"换成"源的期望全集"。
- **跨源冲突**：`(workspace, kb, external_id)` 唯一索引意味着同一 KB 内一个 URL 只属于一个文档。某源 diff 时发现目标 URL 已存在但 `kb_source_id` 指向别的源 → 跳过 + warning `url_owned_by_other_source`（首个源拥有，后者不覆盖、不删除）。
- **源删除语义**：删除源时二选一（UI 强制确认）——①仅删除源行并断开溯源（`documents.kb_source_id` 置 NULL，页面保留，`source_uri` 天然保留 URL 溯源）；②连同该源导入的全部页面一起删除（走既有文档删除路径，含索引清理）。默认 ①。

### 3.3 页面身份与文档模型

- `external_id` 与 `source_uri` 同值：`NormalizeWebSourceURI` 的输出即稳定身份，复用现有 `(workspace, kb, external_id)` 唯一索引与稳定更新语义。
- URL 规范化沿用现有函数，本版本追加一条规则：移除常见跟踪参数（`utm_*`、`fbclid`、`gclid`、`ref` 的保守名单，见 `value/web_source_uri.go` 扩展），不改变既有排序/编码行为；跟踪参数名单作为包内具名常量。
- 目录投影：页面按 URL path 段映射 folder `ExternalNode`（`ObjType='folder'`，`Token`=规范化目录 URL），`HasDocument=false`；页面节点 `ObjType='page'`、`HasDocument=true`、`ParentToken` 指向所属目录。`urls` 模式同构。同一 KB 内多个源的目录树共享 token 空间，同目录自然归并。现有 folder upsert/删除逻辑零改动。
- 标题：ListTree 阶段未必有正文标题（sitemap/urls 模式只有 URL）；节点 `Title` 先用 URL 末段，Fetch 后以抽取标题更新 FileTreeNode/Document（现有 update 路径已支持标题更新）。

### 3.4 模式与快照语义

`ListTree` 对三种模式返回"该源期望的 URL 全集"，`diff`/删除/cursor 语义完全复用：

| mode | ListTree | Complete 语义 | EditTime |
|---|---|---|---|
| `crawl` | 种子 URL 起 BFS（§5.1） | 达到 `max_pages` 截断、单页不可恢复失败导致边界缺失 → `false` | 页面 sitemap 无来源 → 零值 |
| `sitemap` | 解析 sitemap.xml（含 sitemap index 递归、`<urlset>`/`<sitemapindex>`） | XML 拉取失败/解析残缺 → error 或 `false` | `<lastmod>`（缺失→零值） |
| `urls` | 直接返回 `config.urls[]` | 恒 `true`（列表即事实源） | 零值 |

- `crawl` 截断到 `max_pages` 时 `Complete=false`：不删除、不推 cursor、warning 标明 `truncated_at=max_pages`，UI 提示可提高上限续爬。
- `urls` 模式中"从列表移除 URL"等价于远端删除，走源级 `on_delete`；已软删文档的 URL 重新加入列表时按现有"远端重新出现"规则恢复。
- 三种模式共享：normalized URL 去重（同 token 二次出现按现有规则丢弃 + warning）、非 http(s) scheme 跳过、跟踪参数剥离。

## 4. 配置合同

### 4.1 `kb_sources.config`（网站源）

创建时写入、经 typed parser 校验（schemaless jsonb 的校验边界在 application service，同飞书 `sync_root` 做法）：

```json
{
  "mode": "crawl",
  "crawl": {
    "seed_url": "https://docs.example.com/",
    "max_depth": 3,
    "max_pages": 500,
    "include_paths": ["docs/*"],
    "exclude_paths": ["admin/*", "private/*"],
    "allow_subdomains": false,
    "respect_robots": true,
    "request_delay_ms": 200,
    "user_agent": null
  },
  "sitemap": { "url": "https://example.com/sitemap.xml" },
  "urls": ["https://example.com/a", "https://example.com/b"],
  "fetch": {
    "engine": "auto",
    "connection_id": "<uuid|null>",
    "auto_escalate": { "enabled": true, "min_text_chars": 200 }
  },
  "extract": {
    "mode": "readability",
    "target_selector": null,
    "fallback_to_full": true,
    "readability": {
      "char_threshold": 500,
      "nb_top_candidates": 5,
      "classes_to_preserve": [],
      "keep_classes": false
    }
  },
  "sync": { "cron": "0 */6 * * *" },
  "on_delete": "keep"
}
```

规则：

- `mode` 必填且创建后不可变；`seed_url`/`sitemap.url` 创建后不可变（改站点=新建源+删旧源，源的重建成本远低于重建 KB，身份漂移问题随之消解）；
- `urls[]` 只在 `mode=urls` 下有意义，可经 API 增删（§9.2）；
- `crawl.max_pages`/`max_depth` 受 `config.yaml` 天花板钳制（§4.2），超限返回 validation error 而非静默截断；
- `fetch.engine ∈ {auto, http, render, firecrawl, jina}`，**缺省 `http`**（§6.1 引擎表将 http 标为默认；缺省 auto 会令一切无连接的最小配置非法，不自洽）；`engine != http`（含 auto）时 `connection_id` 必填（同 workspace 对应 provider 的 active connection）、`engine=http` 时必须为空；§6.2 的“connection_id 为空时接受结果 + warning”仅指**运行时防御路径**（如连接创建后被删除/停用），不是创建时的合法状态；
- `include_paths`/`exclude_paths` 为 path glob（`*`/`**`），exclude 优先；`allow_subdomains=false` 时仅同 host；为 true 时允许 `*.seed_host`；
- `crawl.*` 中的礼貌性参数（`respect_robots`/`request_delay_ms`/`user_agent`）对三种模式的抓取行为统一生效——键名沿用 `crawl` 仅表示"发现+抓取"的默认参数集，sitemap/urls 模式同样读取，不做第二份配置；
- 运行态键（`sync_cursor`、`next_sync_at`、`sync_requested_force`、`sync_last_result`）在 `kb_sources` 列上，typed API 不得覆盖。

### 4.2 `config.yaml` 新增小节（进程级天花板）

```yaml

  max_depth_ceiling: 10
  render_max_concurrent: 2           # render 引擎全局并发页面上限

```

## 5. 发现层（ListTree 实现）

### 5.1 crawl 模式：受限 BFS

- frontier 为 FIFO 队列，按规范化 URL 去重；`depth(seed)=0`，仅接受 `depth <= max_depth` 的出链；
- 发现阶段的页面请求走与 Fetch 相同的抓取管线（§6），因为从响应中解析出链是发现的一部分；
- 出链提取：`http`/`render` 引擎解析 HTML `<a href>`（resolve 相对链接、去 fragment、规范化后过滤 include/exclude/subdomain/scheme）；`firecrawl` 使用 `formats:["markdown","links"]` 的 links；`jina` 使用 `x-with-links-summary`；
- **发现-抓取复用**：connector 维护本次运行的内存页缓存（`map[normalizedURL]fetchedPage`，容量上限 `min(max_pages, 500)`，超出逐出），`Fetch` 命中缓存直接返回，避免 crawl 模式双倍流量；逐出项回退为真实再抓；
- robots：发现与抓取两个动作前都查 robots；Disallow 的 URL 不进 Nodes，记 warning；
- 单页抓取失败（网络/4xx/5xx）：该页不进 Nodes；若它是某个分支唯一父链，子链自然不可达——由此造成的可能漏删由 `Complete=false` 兜底：连续失败**达到**阈值（具名常量，默认 3，即第 3 次连续失败触发，方向保守）或失败率 >20% 时置 `Complete=false`（失败率在线评估，触发后不可逆）；**种子抓取失败或种子被 robots 拒**：BFS 未开始，整个发现返回 error / `Complete=false`，绝不以"完整空树"参与 diff（否则会误删整源）；
- 礼貌性：同 host 串行 + `request_delay_ms` 间隔；跨 host（allow_subdomains/外链不入集，只同族 host）仍串行——首版不做多 host 并发。

### 5.2 sitemap 模式

- 支持 `sitemapindex` 递归（深度上限具名常量 5）、`<url>` 的 `<loc>`/`<lastmod>`；
- 单个子 sitemap 拉取失败：该子树缺失 → `Complete=false` + warning；主文件失败 → error；
- `<lastmod>` 解析为 `ExternalNode.EditTime` 直接进入现有 cursor/diff 规则；
- sitemap 仅做发现，不取页面正文（条件请求与 hash 在 Fetch 阶段生效）。

### 5.3 urls 模式

- 列表来自 `config.urls[]`，校验/规范化在 API 写入边界完成，ListTree 直接透传；
- 每行一个 URL；非法项在写入时即被拒，不进入列表。

### 5.4 端口签名调整

`FetchedDocument` 增加：


无 connection 的 web 源调用时 `conn` 传零值 `SourceConnection{}`；web connector 从 `options.SourceConfig` 取引擎与参数，凭证由 service 预解密后通过 `SourceConfig["__credentials"]` 注入（内存传递，不落库、不进日志）。

### 5.5 SyncRoot 映射

web 源使用 `SyncRoot{Kind: "web", Token: seed_url | sitemap_url | ""}`；`urls` 模式 Token 为空串，列表从 SourceConfig 读。新增 `sourceport.SyncRootWeb` 常量。

## 6. 抓取层（引擎矩阵）

### 6.1 引擎合同

所有引擎对同一 URL 返回统一内部结果：

```go
type fetchedPage struct {
    FinalURL    string            // 重定向归并后的最终 URL
    Status      int               // HTTP 状态；provider 引擎映射为等价语义
    HTML        []byte            // http/render 通道填；provider 通道可空
    Markdown    []byte            // provider 通道直出；http/render 通道由 §7 抽取生成
    Links       []string          // 发现用出链（已规范化过滤前的原始集合）
    ETag        string
    LastModified string
    Engine      string            // 实际执行引擎
    NotModified bool
}
```

| 引擎 | 实现 | 凭证/端点 | 说明 |
|---|---|---|---|
| `http` | `NewPublicHTTPSClient` + 限速/重试（429/5xx 指数退避，上限 3 次） | 无 | 默认；支持条件请求 |
| `render` | go-rod `MustConnect(cdp_url)` → navigate → `WaitStable`/`WaitRequestIdle` → `outerHTML` | `browser` connection（endpoint_url + 可选 token） | 并发受 `render_max_concurrent` 全局信号量约束 |
| `firecrawl` | `POST {endpoint}/v2/scrape`，`formats:["markdown","links"]`，`onlyMainContent` 映射 `extract.mode` | `firecrawl` connection（api_key + 可选 endpoint 覆盖，默认 `https://api.firecrawl.dev`） | 返回 markdown 直通 |
| `jina` | `GET https://r.jina.ai/<url>`，`X-Engine: auto`（或显式 `browser`/`curl` 映射）、`X-Respond-With: markdown`、`X-With-Links-Summary: all`、`Authorization: Bearer <key>` | `jina` connection（api_key） | 返回 markdown 直通 |

### 6.2 `auto` 渐进升级

`engine=auto` 等价于 `http` 起步 + 命中升级条件时用 `connection_id` 指向的引擎重抓：

- 升级条件（满足其一）：抽取正文字符数 < `auto_escalate.min_text_chars`；JS-shell 启发式命中（body 可见文本 < 阈值且存在 `id="root|app|__next"` 空挂载点，或正文几乎全在 `<noscript>` 中）——判定函数为纯函数 `isLikelyJSShell(html, extractedLen int)`；
- `connection_id` 为空时升级无处可去：接受原结果 + warning `possible_js_shell`；
- 升级重抓记 `source_meta.last_engine` 为实际引擎；同一文档后续同步沿用上次成功引擎（`source_meta` 短路，失败回落再判定）。

### 6.3 robots.txt

- `respect_robots=true`（默认）时：按 origin 拉取 `robots.txt`（SSRF-safe client，TTL 缓存 `robots_cache_ttl_seconds`），用 `robotstxt` 语义匹配抓取 UA；Disallow → 跳过 + warning；
- robots 拉取失败按"允许"处理并记 warning（保守可用性选择，与主流爬虫一致）；
- `render` 引擎在导航前做同样的 robots 校验；`firecrawl`/`jina` 引擎的 robots 行为由 provider 侧决定，文档明确说明琅嬛无法代为执行（firecrawl 遵守目标站 robots，jina 不保证）。

### 6.4 SSRF 分层语义

- `http` 引擎：完整防护——dial 期 IP 校验、redirect 逐跳重校验、私网/环回/链路本地阻断（现有 `internal/adapters/httpclient/ssrf.go`）。**本版本需在该包新增一个 HTTP(S) 变体**：现有 `NewPublicHTTPSClient` 是 HTTPS-only（`validatePublicHTTPSURL` 每次往返强制 https），而 §5.1/§3.3 要求支持 http scheme（非 http(s) 才跳过）。新增变体保留全部防护（dial 期 IP 校验、redirect 逐跳重校验、私网阻断），仅放开 scheme 判定；两种 client 并存，既有调用方不受影响。取舍：放开 scheme 不削弱 SSRF 强度（私网已被 IP 层阻断），代价是明文抓取内容可被中间人篡改——公开网页本身即公开内容，与主流爬虫一致；
- `render` 引擎：导航前在我们侧解析 host 并拒绝私网地址；**但页面加载期的子请求与 DNS 解析发生在浏览器进程侧**，我们的 dial hook 不生效——依赖浏览器侧能力（OxiBrowser 内建 CIDR 阻断、Obscura 默认禁私网 `--allow-private-network`）或部署侧网络隔离。文档与配置校验都必须明示此降级语义；
- `firecrawl`/`jina` 引擎：抓取在 provider 基础设施执行；我们仍在发送前做 URL/host 预校验（解析 + 私网拒绝），但不声称端到端 SSRF 保证；
- 推荐渲染端部署形态写入文档：Obscura（轻量 + 真 V8，默认推荐）→ browserless/headless Chrome（兼容兜底）→ OxiBrowser（极简站点）。

### 6.5 失败分类

- `404/410` → 视为远端删除：不进 `ToAdd`，已在本地的进 `ToRemove`（受 Complete 闸门约束）；
- 非 HTML 内容类型（`Content-Type` 非 HTML，见 §7）→ 跳过 + warning `skipped_non_html`，不算 retryable；
- `401/403`（认证墙）、robots 禁止 → 跳过 + warning，不算 retryable；
- 网络错误、`429`/`5xx`、超时、超限 → `ErrSourceUnavailable`/oversize 语义，走 `RetryRequired`；
- provider 配额/鉴权失败 → `ErrSourceUnavailable`，Job 级 partial/failed 按现有分类。

## 7. 抽取层（http/render 通道）

- 管线：`HTML → (可选 target_selector 圈定) → readability（参数化 Parser）→ article HTML → html-to-markdown → markdown`；
- readability 采用 `go-shiori/go-readability`，`Parser` 字段从 `extract.readability` 映射；`CharThresholds` 未达标按库内重试语义处理；
- `fallback_to_full=true` 且 readability 产物仍为空/低于阈值 → 对整页（或 `target_selector` 圈定区）直接 html-to-markdown，记 warning `readability_fallback`；
- `extract.mode=full` 跳过 readability；
- **参数集对齐所选 readability 实现的实际字段**：`extract.readability` 只保留实现真实支持的键（`link_density_modifier` 已从 §4.1 合同中移除——所选实现在该版本无对应字段，保留会形成"配了不生效"的陷阱）；
- **非 HTML 响应跳过**（对应 §1 的"PDF/DOC 链接记 warning 跳过"）：响应 `Content-Type` 非 `text/html`/`application/xhtml+xml`（含缺失时按 HTML 尝试）→ 不抽取、不进 Nodes，记 warning `skipped_non_html`，不算 retryable；
- provider 通道 markdown 直通，不跑本地抽取（`extract` 仅映射到 provider 侧等价选项：firecrawl `onlyMainContent`、jina 默认 readability 过滤）；
- 抽取产物落 `FetchedDocument.Markdown`，进入现有 `max_content_bytes` 双检与 hash 流程；图片链接由下游 `AssetResolver` 归档，沿用 `MaxCountPerDocument` 等现有限额。

## 8. 增量与更新检测

三级递进，全部落在既有事实上，无新增状态机（游标按源隔离，互不干扰）：

1. **`EditTime`（sitemap lastmod）**：走现有 cursor/diff——`<= cursor` 且无重试需求直接 `Skipped`；crawl/urls 无 lastmod 时 EditTime 零值，天然落到 Fetch+hash 路径；
2. **HTTP 条件请求**（仅 `http` 引擎）：Fetch 带 `If-None-Match`/`If-Modified-Since`（来自 `documents.source_meta`），`304` → `NotModified`，按 `unchanged` 处理、刷新 `last_fetch_at`，不建 revision；`200` → 正常抽取并更新 etag/last_modified；
3. **`content_hash` 兜底**：render/provider 无条件语义，抓回后 hash 相同不建 revision（现有机制）。

`localDocView` 增加 `SourceMeta` 视图字段；`UpdateDocumentRequest`/新建路径在同一事务写 `content_hash`、`source_meta` 与 `kb_source_id`。force 语义不变：全量重抓、hash 未变也建新 revision。

## 9. 调度、API 与消费面

### 9.1 调度与执行隔离（双轨并行，同一任务类型）

- **爬取只发生在队列 worker 内**：调度器（cron 扫描）与一切 API 入口只负责入队与合并，任何路径不得以进程内 goroutine / 请求内联方式直接爬取——飞书同步既有约束，web 源显式沿用；
- 飞书路径完全不动：`ListDueFeishuKBs` 及 KB 级编排保持现状；
- 新增 `ListDueWebSources`（`kb_sources` 中 `status='active'` 且 `next_sync_at <= now`），入队与飞书相同的 `source_sync` 任务类型，任务 target 为源 ID（`jobs_target_check` 增加源级分支，§10）；
- 分组限流：有 `connection_id` 的源按 connection 组（沿用 `max_concurrent_per_connection`）；无 connection 的源每组额度 1（同源单 active 由入队合并逻辑保证）；
- **全局在飞上限**：`web_source.max_concurrent_syncs`（默认 2）——Meta Scheduler 在 connection 分组之上追加全局计数（**仅统计 target 为 web 源的 active source_sync Job**；飞书任务由其既有 connection 限额管辖，不占此配额），上限内才入队，超额到期源留待下次扫描或 worker 完成后的续跑。动机：asynq 队列权重只是调度优先级、全局 `queue.concurrency`（默认 8）由全部任务类型共享，不做在飞封顶的话，多个长爬取会挤占 parse/index 等短任务的 worker 槽；
- **任务超时按源推导**：入队 Timeout 取 `min(页数基准 × (request_timeout_seconds + request_delay_ms) × 2, web_source.sync_task_timeout_seconds)`（硬上限默认 4 小时）。页数基准：crawl=`crawl.max_pages`；urls=`len(urls)`；sitemap=具名常量 500（发现前不可知，与 §5.1 页缓存上限同源）。推导值必须显式覆盖全局 `queue.task_timeout_seconds`（30 分钟）默认——否则触及 `max_pages_ceiling` 的爬取会陷入"超时→重试→再超时"循环，反复占用 worker；standalone 内存队列路径同样受上述约束（Meta Scheduler 为进程内逻辑，在飞计数同样生效）；
- 源完成时触发同 connection 续跑检查（latch 恢复路径复用）；同源串行由"入队前检查该源是否已有 running 任务"保证；任务超时/中断后的恢复语义 = 现有 cursor watermark + diff 幂等，重跑不重复建 revision。

### 9.2 REST（全部挂在 KB 下，admin/owner 管理位、member 只读）

- `POST .../knowledge-bases/{kb}/web-sources`：创建源（§4.1 config typed 校验、`connection_id` 校验 provider 匹配与同 workspace、`max_sources_per_kb` 钳制）；返回 `201`（响应体含首次同步入队的 `job_id`）；
- `GET .../web-sources`：源列表（config 非敏感子集 + 状态 + `sync_last_result` + 页面计数）；
- `PATCH .../web-sources/{id}`：允许键 `name`、`urls`（整体替换；被移除的 URL 下次同步按 `on_delete` 生效）、`crawl.{max_depth,max_pages,include_paths,exclude_paths,allow_subdomains,respect_robots,request_delay_ms,user_agent}`、`fetch.*`、`extract.*`、`sync.cron`、`on_delete`、`status`（启停）；拒绝 `mode`、`crawl.seed_url`、`sitemap.url`、`connection_id`（引擎/连接创建后不可变，需要时新建源替换）；**PATCH 成功返回 `200`（响应体含本次入队的 `job_id`），即入队同步**；
- `POST .../web-sources/{id}/sync` `{"force":bool}`：手动重跑（force=全量重爬）；
- `DELETE .../web-sources/{id}?pages=keep|remove`：删除源，页面处置二选一（§3.2，默认 keep）；
- KB detail 响应不扩字段（源不在 KB 行上）；现有 `sync_last_result` 语义仅飞书 KB 使用，不变。

### 9.3 MCP

- `document_ingest` 增加可选 `url` 字段：语义为"把该 URL 加入目标 KB 的 urls 模式网站源并触发同步"；要求该 KB 恰有一个 `mode=urls` 的 active 网站源——没有则返回 validation error 提示先创建，多个则 error 列出让调用方指定（本版不加 source 选择参数，保持工具面最小）；

## 10. 数据与迁移（`000025_web_source` + `000026_web_source_tree`）

1. 新建 `kb_sources` 表（§3.2），含 `(workspace_id, kb_id)` 索引与部分唯一/软删约定（`deleted_at IS NULL`）；`kind` CHECK 本版仅 `'web'`；
2. `documents` 新增 `kb_source_id uuid NULL REFERENCES kb_sources(id)` + `source_meta jsonb NOT NULL DEFAULT '{}'`，并建 `(kb_source_id)` 索引（按源计数/清理用）；
3. `workspace_source_connections_provider_check` 放宽为 `('feishu','firecrawl','jina','browser')`；
4. `jobs_target_check`：`source_sync`/`source_cleanup` 分支增加源级目标校验——target 为 `kb_sources.id` 时要求源存在、未删除、所属 KB 未删除（KB 级飞书分支原样保留）；`jobs.kb_source_id` 列 + 复合 FK + 部分索引（源级任务的载体，触发器仅在目标列变化时校验——不冻结在飞任务）；
5. **`000026_web_source_tree`（T8 实现期发现的必要迁移）**：file_tree_nodes / document_revisions 的 shape 复合外键把 `document_kind`/`kind` 与 `documents.kind` 绑定，且 Row 层此前硬编码 `'file'`——web 页面建档在真实 PG 必失败（单测测不出，集成测试抓到）。该迁移放宽 shape_check 纳入 `'web'`、FileTreeNode 模型放宽 `file|web`、revision kind 继承文档 kind（web 分支禁 OriginalFilename/FileType）；SQLite 快照同步对齐；
6. down migration 逆序还原（删列/删表/还原 CHECK 与 target_check 函数），不清理 jsonb 运行态键。

说明：

- `knowledge_bases.source_type` CHECK **不动**（本版核心决策：网站不是 KB 类型）；
- `documents.source_type` 无枚举 CHECK，web 文档写 `'web'`；`uq_*_external` 索引以 `(workspace, kb, external_id)` 为界，天然支持多源同库与跨源冲突裁决（§3.2）；
- `workspace_source_connections` 的 `(workspace,provider,config->>'app_id')` 唯一索引对无 `app_id` 的 provider 自然失效（NULL 不参与冲突），provider 级唯一键差异由 `(workspace,provider,name)` 兜底，不新增索引；
- `SourceConnection` 模型放宽：`app_id` 仅 feishu 必填；`firecrawl`/`jina` 要求凭证密文非空；`browser` 允许空密文（endpoint 在 config）。`NewSourceConnection` 改为 per-provider 字段校验。

### 12.4 验收标准

1. 同一 KB 内：上传文件 + 两种以上模式的网站源共存，页面与文件同场检索命中；页面文档可按来源溯源；

3. `auto` 引擎对静态页不触发渲染，对 JS-shell 页升级到已配置引擎并在 `source_meta` 留痕；

## 13. 分阶段交付

- **Slice 1（本地链路）**：迁移（kb_sources/documents 列/target_check）+ domain value/config parser + `kb_source` service 骨架 + web connector（http 引擎 + 三模式发现 + readability 抽取 + robots + 限速）+ 源级编排与调度接入 + httptest e2e；
- **Slice 2（高级引擎）**：`browser`/`firecrawl`/`jina` connection provider + render/provider fetcher + auto 升级 + 条件请求（etag/last_modified 持久化）+ 跨源冲突与源删除分支；
- **Slice 3（消费面）**：web-sources REST、MCP url 入口、Web Console（Web 子 tab 请求列表/源详情/源表单/管理 URL 对话框/连接 provider 表单）、文档（ARCHITECTURE/API_ACCESS/config.example/部署侧的渲染端推荐矩阵）。

## 14. 明确取舍

1. **源级建模而非站点级 KB**（本版核心裁决）：KB 是检索域，混装避免知识被人为拆库、跨库合并成本转嫁调用方；代价是同步编排键从 KB 泛化为源（`kb_sources` 新实体 + `documents.kb_source_id`），以及跨源 URL 冲突需要归属裁决；
2. **发现与删除判定始终留在琅嬛侧**，provider 只做单页抓取——保住 `Complete` 闸门与 `on_delete` 语义不被外包稀释；
3. render 不内嵌浏览器：`cdp_url` 是唯一接口，换来单二进制交付不破；代价是 render 的 SSRF 保证弱于 http，已在 §6.4 明示；
4. crawl 发现期复用抓取管线 + 每 run 页缓存，接受"逐出后可能二次抓取"的小概率浪费，换取 ListTree/Fetch 接口不变；
5. `mode`/seed/engine/connection 创建后不可变：改站点=新建源替换旧源——源是轻量实体，重建成本可接受，换取 external_id 语义不漂移；
