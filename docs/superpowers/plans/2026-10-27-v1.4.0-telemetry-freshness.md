**Goal:** 把已发生但不可见的事实变成维护闭环：检索完成处旁路落库 chunk 级引用遥测（`search_citations`）与 opt-in 查询原文（`search_query_log`，默认关闭）；工作台新增「健康」tab——空召回率北极星、零召回查询 Top N、沉睡内容 Top N、四源统一内容动态 feed；行动全部挂既有端点（零召回→预填 FAQ、沉睡→查看、源变更→强制重爬补 UI）；文档删除前引用预警；检索结果透出新鲜度元数据。不写任何新的变更检测代码。

**Architecture:** 采集 = SearchRun 流程末尾的非阻塞投递（进程内有界缓冲 + 批量落库，standalone/PG 双模式同构，不用 asynq）；洞察 = 只读 SQL 聚合（日桶在 Go 侧补齐、UNION ALL + Go 侧归并，规避方言函数；确需方言分支走 `db.Dialect` 先例）；行动 = 既有端点 + 一处新写入口（query-log 开关）；验证 = 查询级空召回率环比（删了重传会换 document 身份，文档级指标断裂）。

**Tech Stack:** Go 1.26、Gin、GORM/pgvector（+SQLite standalone）；零新增后端依赖、零新增前端库。前端 React 19 + TanStack Router/Query + RHF + Zod + i18n（zh/en 双份）。

## Global Constraints

- **隐私铁律**：`search_runs` 表与写入路径**零改动**；`query_text` 仅存在于 `search_query_log`（仅 `query_log_enabled=true` 的 KB 写入），任何日志、错误信息、指标、MCP 响应不得包含明文；明文门控在**投递侧构造时**决定，不做事后过滤。
- **热路径旁路**：引用投递非阻塞、缓冲满即丢批 + 计数器 + 结构化日志；检索响应 P99 不得受影响（T5 故障注入断言）；flusher goroutine 必须随 server 生命周期启停（AGENTS 5.8）。
- **遥测表无跨表级联 FK（D3）**：引用行必须活过 run 过期清理与文档清理（删除预警依赖"文档已删、引用历史还在"）；生命周期由 `insights.*_retention_days` 独立清理。
- **指标口径**（spec §4.5）：空召回率 = `empty / (available + empty + degraded)`，failed 剔除分母；聚合排除 `transport='console'`。现状核实：transport 现取值仅 `rest`/`mcp`（`request_id.go`），console 标记为本版新增。
- **排序零改动**：`make eval` 回归标注"不适用"（无 chunker/RRF/embedding 变更）；`detail=lean` ≤15000 字符断言必须重跑。
- 遥测表查询侧一律显式 `workspace_id` 过滤；跨 workspace 一律 404；测试数据库只用临时 docker pgvector/zhparser 容器（AGENTS 5.10），不发真实网络请求。
- 前端：全部新文案进 i18n zh/en（en `satisfies` 对齐）；不引图表库（环比用文字）；复用现有组件范式（计数卡/最近任务行/StatusBadge/border-dashed 空态/DeleteDialog）。
- 提交：Conventional Commits 中文；迁移/domain/service/REST/console 分批提交，结构与行为修改分开。
