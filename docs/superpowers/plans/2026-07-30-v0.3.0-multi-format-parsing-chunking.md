# 琅嬛 v0.3.0 多格式解析与分块 Implementation Plan

> **完成状态：** 2026-07-30 已完成。普通回归使用 `go test ./... -count=1`；真实 PostgreSQL/Redis/asynq/HTTP 验收使用 `go test -tags integration ./cmd/langhuan -run 'TestV030MultiFormatHTTPWorkerE2E|TestV030PDFRejectedWithoutPersistenceE2E' -count=1 -v`。完整门禁见 Task 10。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 实现 Markdown、TXT、CSV、XLSX、DOCX 的真实本地解析、版本化 parse manifest、结构化分块与完整异步 E2E，使五种格式从 REST 上传到 `completed`，并在持久化前拒绝 PDF。

**Architecture:** `DocumentIngestService` 先规范化并校验格式，再保存 raw document 与 processing version 1 Document；worker 通过 `RawDocumentStore.Open` 读取真实内容，Parser Registry 路由到格式 adapter，parser 用共享 builder 生成 normalized Markdown 与结构 span。`document_index` 读取知识库 `chunking_config`，由应用层纯 Chunker 生成 content、embedding content、context header 与 typed source anchor，再由 repository 事务性批量替换 chunks。

**Tech Stack:** Go 1.26、Gin、GORM、PostgreSQL、pgvector、Redis、asynq、Goldmark、Excelize v2、Go 标准库 `archive/zip`/`encoding/xml`、YAML。

## Global Constraints

- 严格 Red → Green → Refactor；生产行为必须先有已确认失败的测试。
- domain model 不带 JSON/GORM tag；JSONB 在 `internal/infrastructure/db` 使用 `JSONMap` 与显式 codec。
- 分块单位固定为 Unicode rune；默认 `512/80`，`overlap=0` 合法，`overlap < size`。
- 只支持 `markdown/md/txt/csv/xlsx/docx`；PDF 在 raw、Document、Job 之前返回 HTTP 415。
- DOCX 只处理正文标题、段落、列表、表格；图片只生成 warning。
- CSV/XLSX 每 sheet 独立、首个非空行作表头、table chunk 重复表头、公式用显示/缓存值。
- Office ZIP entry <= 10,000，总解压 <= 512 MiB，单 XML part <= 128 MiB。
- 不实现 PDF/MinerU、图片归档、Embedding、pgvector/FTS 写入、搜索、MCP 业务工具或 Web Console。
- workspace 隔离不变；日志不含完整原文、单元格内容、密码或二进制。
- 每个任务 GREEN 后运行 `go test ./... -count=1`，保证中间提交可编译、可回归。
- 最终必须通过 `gofmt -w .`、`go test ./... -count=1`、`go vet ./...`、`git diff --check` 和真实 PostgreSQL + Redis + HTTP + worker E2E。
