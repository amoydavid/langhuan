# 琅嬛 v0.6.0 Workspace API Key、MCP 与程序化访问 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 v0.5.0 基线上交付可重复 reveal、按一个或多个 KnowledgeBase 限权、可到期或不限期的 Workspace API Key，并通过 REST 与 `mcp-go` Streamable HTTP 提供一致的六项程序化能力，其中 `knowledge_search` 支持跨多个知识库按 Embedding 模型快照分组检索和确定性合并。

**Architecture:** 浏览器继续使用 Session，程序化入口使用 opaque Bearer API Key；认证索引只保存 SHA-256 hash，可恢复明文另用 HKDF 派生子密钥和 AES-256-GCM 加密。HTTP 与 MCP 共享协议中立的 `AuthContext`、`ResourceAccess` 和 application service；多库检索由 application 协调器一次性校验范围、按五元模型身份分组复用 query embedding，再以统一 RRF 分数全局合并。所有 Workspace 持久化经 `WorkspaceTxRunner` 和显式 `workspace_id` 约束，Web Console 只把 reveal secret 放在详情页局部内存。

**Tech Stack:** Go 1.26、Gin、GORM、PostgreSQL 16 + pgvector、Redis/asynq、`github.com/mark3labs/mcp-go v0.57.0`、HKDF-SHA-256、AES-256-GCM、React 19、TypeScript 7、TanStack Router/Query、React Hook Form + Zod、Tailwind CSS v4、shadcn/ui、Vitest Browser、Biome。

## Global Constraints

- `server.public_base_url` 破坏性改名为必填的全局 `server.base_url`，不保留旧 alias；Web、REST、MCP、邀请链接分别只从它派生 `${base_url}/`、`${base_url}/api/v1`、`${base_url}/mcp` 和应用路径。
- API Key 明文固定为 `lhk_` 加 32-byte `crypto/rand` 随机值的无 padding Base64URL 编码，总长 47 个 ASCII 字符；鉴权只使用完整明文的 SHA-256 lowercase hex。
- 可恢复 secret 必须从现有 `credentials.encryption_key` 通过 HKDF-SHA-256、info `langhuan/workspace-api-key/v1` 派生独立 32-byte key，再用 AES-256-GCM、随机 nonce、版本字节及 AAD `workspace-api-key:v1:<workspace_id>:<api_key_id>` 加密；普通鉴权禁止读取或解密密文。
- owner/admin 可在创建后任意次数 reveal/复制 active、expiring、expired 或 revoked key；reveal 必须是 Session-only `POST`，响应带 `Cache-Control: no-store` 与 `Pragma: no-cache`，且不进入 Query Cache、URL、Zustand 或 Web Storage。
- 每个 API Key 创建时必须绑定当前 Workspace 内至少一个未删除 KnowledgeBase；绑定创建后不可修改。唯一扩展例外是带 `knowledge_bases:write` 的 key 创建新知识库时，新 KnowledgeBase 与新 binding 必须在同一事务提交。
- scope 只允许 `knowledge_bases:write`、`documents:read`、`documents:write`、`search:read`，无隐式继承；API Key 越 Workspace、越 KnowledgeBase 或访问绑定外的 Document/Job/Chunk 时统一返回 `404`。
- 到期请求使用 `{"type":"days","days":N}` 或 `{"type":"never"}`；`expires_at=NULL` 表示不限期。吊销即时影响下一次请求，不声称中断已进入 application service 的请求。
- `knowledge_search` 必须先验证全部 1..20 个 KnowledgeBase ID，再按 `embedding_model_id + provider_id + model_name + embedding_dimension + model_config_hash` 分组；每组只生成一次 query embedding，任一组失败则全部失败。
- 多库结果统一使用 `search.multi_merge_rrf_k=60`，按 `score DESC, knowledge_base_id ASC, chunk_id ASC` 稳定排序后应用全局 `final_top_k`；结果必须包含 `knowledge_base_id` 和 `knowledge_base_name`，不得直接比较不同模型的 cosine/distance。
- MCP 固定升级并锁定 `github.com/mark3labs/mcp-go v0.57.0`，使用 stateless、non-streaming Streamable HTTP、typed input/output schema、scope tool filter、recovery 和 output validation；不得自研 JSON-RPC、stdio MCP、OAuth metadata 或动态工具注册。
- 所有 I/O 透传请求 `context.Context`；并发使用 `errgroup.WithContext`，默认并发 4，不启动脱离请求生命周期的 goroutine。
- domain/application 不依赖 GORM；Repository 使用 Row/领域双层模型，Workspace 查询带显式 `workspace_id`，tenant 表使用 `UNIQUE(workspace_id,id)` 或 `UNIQUE(id,workspace_id)` 与 composite FK。
- 所有数据库、集成和 E2E 测试只允许测试运行期临时启动的 `pgvector/pgvector:pg16`，不得读取 `config.yaml` 或连接本机长期 PostgreSQL。
- 所有行为按 Red → Green → Refactor 实现；前端请求使用统一 axios client + TanStack Query，表单使用 RHF + Zod，样式使用 Tailwind/shadcn，禁止 `any`，禁止手改 `web/src/routeTree.gen.ts`。
- 日志、错误、Toast、诊断、测试输出及常驻 DOM 不得包含完整 API Key、token hash、ciphertext、Provider credential 或完整文档 payload。
- v0.6.0 不实现 OAuth/OIDC/JWT、限流计费、审计事件、Rerank、LLM 回答、API Key scope/binding 编辑、在线主密钥轮换或物理删除历史 key。
- 每个任务结束先更新本计划 checkbox，再把计划与实现纳入同一 Conventional Commit；提交主题与正文使用中文为主。

```go
func GenerateAPIKeyMaterial(random io.Reader) (APIKeyMaterial, error) {
    secret := make([]byte, 32)
    if _, err := io.ReadFull(random, secret); err != nil { return APIKeyMaterial{}, fmt.Errorf("生成 API Key: %w", err) }
    plaintext := "lhk_" + base64.RawURLEncoding.EncodeToString(secret)
    sum := sha256.Sum256([]byte(plaintext))
    return APIKeyMaterial{Plaintext: plaintext, Hash: hex.EncodeToString(sum[:]), Prefix: plaintext[:12]}, nil
}

func deriveAPIKeyPurposeKey(master []byte) ([]byte, error) {
    derived := make([]byte, 32)
    _, err := io.ReadFull(hkdf.New(sha256.New, master, nil, []byte("langhuan/workspace-api-key/v1")), derived)
    return derived, err
}
```

```go
    key, err := s.store.FindByTokenHashWithBindings(ctx, hash)
```

```go
        return results[i].KnowledgeBaseID.String() < results[j].KnowledgeBaseID.String()
    }
    return results[i].ChunkID.String() < results[j].ChunkID.String()
})
```

执行顺序固定为：trim/query 校验 → KB IDs 去重且 1..limit → 在一个 Workspace read 中加载全部 KB 名称和 ready active Generation → 全部 access 校验 → 按五元组分组 → `errgroup.WithContext` + semaphore(4) 每组 resolve/一次 embed → 每 KB 用共同 `multi_merge_rrf_k` 做 vector/keyword RRF → 合并 model-independent score → 再确认各 Generation ID 未切换 → 稳定排序与全局截断 → 加载完整 evidence。任一 Generation 变化返回稳定 `generation_stale`；任何 provider、维度、generation 或 repository 错误取消同组请求并整单失败。
