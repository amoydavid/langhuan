# 琅嬛 v0.2.1 多租户与认证 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** 实现以 workspace 为租户边界的 email/password 认证、数据库 session、成员角色和邀请注册，并保持既有 worker/asynq 继续仅使用 workspace UUID。

**Architecture:** HTTP URL 使用 workspace slug。SessionAuth 从 cookie 解析持久 session 和 user，RequireWorkspace 将 slug 解析为 UUID 并验证 membership，随后 handler 只读取 AuthContext。application service 依赖 password/rate-limit 端口，adapter 分别实现 argon2id 与 Redis；worker 完全不经过该链路。

**Tech Stack:** Go 1.26、Gin、GORM、PostgreSQL、golang-migrate、Redis、argon2id、crypto/rand、crypto/sha256、miniredis、YAML。

## Global Constraints

- 只交付 email + password + nickname；不实现 OIDC、SSO、API token、密码邮件重置或前端。
- 密码仅保存 argon2id；默认 memory=65536 KiB、iterations=3、parallelism=2；明文密码、token、session ID 不得进入日志、响应、commit。
- Cookie 默认 langhuan_session、604800 秒、HttpOnly、SameSite=Lax；示例配置 secure_cookie=true。
- invitation token 必须随机 32 bytes、base64url；数据库仅保存 SHA-256 hash 和前 8 位 prefix。
- slug 必填、唯一、符合 ^[a-z0-9](?:[a-z0-9-]{1,62}[a-z0-9])?$；HTTP 入口用 slug，其余层只用 UUID。
- 角色是 owner/admin/member，顺序 member < admin < owner；不得删除或降级最后 owner。
- 无 session 为 401；无 membership 统一 404；角色不足 403；登录阈值为 429。
- 仅首个用户可无 invitation 注册并成为 platform_admin，且不自动加入 workspace。
- schema 只新增 000002 手写 SQL migration；worker、asynq payload、既有 workspace UUID repository 过滤零改动。
- 全程 Red → Green → Refactor；每个 Chunk 完成后单独提交。

## 路由契约

| Method | Path | 最低权限 |
|---|---|---|
| POST | /auth/register | 公开，首次或带 invitation_token |
| POST | /auth/login | 公开 |
| POST | /auth/logout | 已登录 |
| GET | /auth/me | 已登录 |
| GET | /invitations/:token | 公开，仅 pending invitation |
| POST | /api/v1/workspaces | platform_admin |
| GET | /api/v1/workspaces/:workspace_slug | member |
| GET | /api/v1/workspaces/:workspace_slug/members | member |
| PATCH, DELETE | /api/v1/workspaces/:workspace_slug/members/:user_id | owner |
| POST | /api/v1/workspaces/:workspace_slug/invitations | admin |
| DELETE | /api/v1/workspaces/:workspace_slug/invitations/:invitation_id | 创建该邀请的 admin/owner |
| DELETE | /api/v1/invitations/:invitation_id | platform_admin |
| POST | /admin/users/:user_id/password-reset | platform_admin |
| POST, GET | /api/v1/workspaces/:workspace_slug/knowledge-bases, documents, jobs | member |

创建 workspace body 为 name、slug、metadata；创建与发起者 owner membership 必须同一事务。成员 PATCH body 为 role。创建邀请 body 为 invited_email、role，返回 id、email、role、expires_at、token_prefix、invite_url；明文 token 只在这次响应的 invite_url 中出现。

迁移对旧 workspace 回填 slug：DefaultWorkspaceID 使用 default，其他使用 legacy-<uuid>。删除 buildApp 的 EnsureDefaultWorkspace 调用，避免认证启用后创建无 owner 租户；保留 helper 仅供旧库迁移兼容测试。
